# Annual Report Q&A — hybrid RAG over Indian listed-company annual reports

> Work in progress. Ask a question about a Nifty 50 company's annual report and get a cited answer, in ₹ crore, with the passages it came from. Built to compare retrieval strategies honestly, not to demo a chatbot.

## Why

Indian annual reports are 200–400-page designed PDFs. The answer to "what did HDFC Bank say about credit costs in FY25?" is in there — usually in the MD&A or a note to the accounts — but finding it is a Ctrl-F exercise. And unlike US 10-Ks, every company lays its report out differently, so the parsing is real engineering, not a library call.

## What's in v1

- 10 Nifty 50 companies × FY24 and FY25 = 20 reports
- Section-aware parsing (Chairman's letter, MD&A, Directors' Report, Risk Management, consolidated financials)
- Three retrievers behind one interface: BM25, dense vector, hybrid (RRF) + cross-encoder reranker
- Cited answers with company / FY / section / page; figures normalised to ₹ crore
- A 60-question evaluation set with gold passages and a script that scores every retriever

## Setup

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
pip install -e .
```

## Run

```bash
python -m arqa.fetch            # download PDFs listed in data/sources.csv
python -m arqa.parse            # PDFs -> data/processed/*.jsonl
python -m arqa.chunk            # sections -> data/chunks.jsonl (page-ranged, ~500 tokens)
python -m arqa.index            # BM25 + FAISS into index_store/
python eval/run_eval.py         # score bm25 / dense / hybrid / hybrid+rerank -> eval/results.md
python -m arqa.ask "What free cash flow did Infosys generate in FY25?" --ticker INFY --fy FY25
python -m arqa.ask "How did Retail EBITDA move?" --ticker RELIANCE --fy FY24 --fy FY25
python eval/run_answer_eval.py  # answer accuracy (LLM judge) + citation accuracy -> eval/answer_results.md
pytest -q
```

## Results

Retrieval quality on the 62-question set, k = 5, each question filtered to its company and year. `eval/results.md` is regenerated by `python eval/run_eval.py`.

| retriever | hit rate | R@5 | MRR | factual hit | conceptual hit | cross-year hit | unit-trap hit | s / question |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| BM25 | 0.85 | 0.82 | 0.66 | 0.91 | 0.85 | 0.70 | 0.90 | 0.08 |
| dense (bge-small) | 0.73 | 0.69 | 0.51 | 0.73 | **0.95** | 0.50 | 0.50 | 0.05 |
| hybrid (RRF) | 0.85 | 0.82 | 0.67 | 0.86 | 0.90 | 0.70 | 0.90 | 0.15 |
| hybrid + cross-encoder rerank | **0.90** | **0.86** | **0.73** | **0.91** | **0.95** | **0.80** | **0.90** | 2.98 |

What the table says (62 questions is small; treat differences under ~5 points as noise):

- **BM25 beats the dense retriever on this corpus** — 0.85 vs 0.73 hit rate. Annual-report questions are full of exact tokens (₹ figures, "FY25", "payout ratio", a product name) that lexical search nails and a small general-purpose embedding model blurs. Dense retrieval wins only on *conceptual* questions (0.95 vs 0.85), where the wording of the question and the passage differ.
- **Unit traps punish dense retrieval** — 0.50 vs 0.90. Numbers and currency units carry almost no signal in the embedding.
- **Hybrid fusion is a free lunch only in the ranking** — same hit rate as BM25, but it keeps dense's conceptual wins, so the blend is safer than either alone.
- **The reranker is worth it at the top of the list**: +5 points hit rate, MRR 0.67 → 0.73 (the right page moves from rank ~2 to rank ~1.4), for 20× the latency (3 s/question on a laptop CPU). For a cited-answer system the LLM reads the top 3–5 chunks, so rank matters more than recall@50.
- **Cross-year questions are the hardest kind** (0.60 R@5 at best): they need two pages from two reports in one top-5, which is a retrieval-budget problem, not a relevance one — the week-3 answerer will issue one retrieval per year.

### Answer results (first run, 61 of 62 questions — Groq free-tier cap stopped the last one)

Retriever hybrid + rerank, k = 5, answerer `openai/gpt-oss-120b`, judge `openai/gpt-oss-20b`, both on Groq's free tier.

| | correct | partial | wrong | cited a gold page |
| --- | --- | --- | --- | --- |
| all 61 | **38 (62%)** | 9 | 14 | 37 |

What the 23 non-correct answers were, after reading every one:

- **Unit-trap questions answered "not found" (3).** The model extracted the US$ figure, put it in the figures list, and still declared the answer not found because the question asked for ₹ crore. Fixed in code: an extracted figure *is* a finding.
- **Right answer, no citation (6).** The `[n]` marker was missing or written as `【2】`. Fixed: accept both bracket styles and fall back to the citation each figure carries.
- **Right answer, "wrong" page (4).** The same fact appears on several pages — TCS's deal TCV is in the highlights *and* the Chairman's letter — and the gold set listed one. Fixed: the question file now carries verified alternate pages for those.
- **Gold page not retrieved, or retrieved and misread (~8).** HDFC's net interest income, L&T's order book, HUL's Home Care FY25 revenue, Bajaj's unclaimed deposits. The eval now records the retrieved passages and a *gold page retrieved* flag, so the second run splits these into retrieval failures and reading failures — the fix is different for each.
- **Conceptual "partial" (7).** The judge wants every sub-point of a long gold answer; the system gives the main three. Accepted for now.

The second run, with these fixes, is the before/after table that replaces this one.

### How the eval set was built

`data/eval/questions.jsonl` has 62 questions over the 10 companies: 22 factual, 20 conceptual, 10 cross-year, 10 unit traps. Each carries the PDF page(s) the answer sits on and a short verbatim quote from that page; a check script confirms every quote is a substring of its page's extracted text, so the gold pages are real, not remembered. The questions were drafted with an LLM reading the extracted page text, then checked the same way — the guide for writing more by hand is `data/eval/README.md`. Scoring is page-overlap: a retrieved chunk counts when its page range touches a gold page.

## Parsing notes by company

The parser finds chapter headings in the top lines of each page (PyMuPDF, `sort=True`), ranks competing matches by specificity, and treats governance / BRSR / standalone / AGM-notice headings as *closers* so a chapter can't swallow what follows it. Things the first run on real reports taught it:

- **"Dear Shareholders" is not a heading.** HDFC Bank's Directors' Report opens with it; a generic pattern for it mislabelled the whole report as the Chairman's letter. Specific headings now outrank generic ones.
- **Nav strips.** L&T and HUL print "Corporate Overview | Management Discussion and Analysis | …" at the top of every page. Any line recurring on ≥25% of pages is treated as boilerplate.
- **Two-line headings.** L&T sets "Chairman's / Statement" on two lines; adjacent short lines are also tried joined.
- **Nested chapters.** At HDFC Bank the MD&A sits inside the Directors' Report; at HUL the chapter is literally "Report of Board of Directors and Management Discussion and Analysis". A sub-heading below a chapter's running header opens a sub-section; one-page flapping between the two is merged afterwards.
- **Reliance** titles the letter "Chairman and Managing Director's Statement" and splits the MD&A into "Management Discussion and Analysis — Business Overview / Financial Performance / Risk and Governance".
- **ICICI Bank** publishes the Integrated Report, Board's Report and financial statements as separate PDFs; `sources.csv` has a `part` column for that. Its Board's Report PDF carries "BOARD'S REPORT" on all 49 pages — a repeated line that *is* a target heading is never treated as boilerplate.
- **TCS**'s font encoding scatters spaces inside words ("Man ag ement Discussion an d Anal ysis"), sets titles over three lines, and puts page numbers beside running headers ("79  Management Discussion and Analysis"). Headings are matched against a whitespace-stripped copy as well; leading/trailing page numbers are stripped; two- and three-line joins are tried.
- **HDFC Bank** letter-spaces its chapter titles ("D I R E C T O R S ' R E P O R T"); the whitespace-stripped match covers that too. Its MD&A is a section inside the Directors' Report.
- **HUL** pads headings with ~70 zero-width spaces, which pushed them past the heading-length limit. Invisible characters are scrubbed before anything looks at a line.
- **Contents pages** that put the page number first ("67  Board's Report") are detected by counting number-led lines — but only within the first 15 pages, because a balance sheet's note numbers look the same.
- **L&T**'s MD&A is a run of segment reviews ("IT & Technology Services Segment", "Overall Financial Review"); those are closers so the Risk chapter ends where it should.
- **Headings are (almost) the whole line.** HDFC Bank FY25 p22 is a director's bio in two columns; one line reads "Risk Management and Corporate in any other listed company." and opened a 40-page phantom Risk chapter. A match followed by a long, mostly lower-case tail is now a sentence, not a heading — while a nav strip glued onto a title (HUL: "Consolidated Balance Sheet Overview Overview … Statements") still counts.
- **A bare "Independent Auditor's Report"** opens the standalone accounts (Reliance, Tata Motors). Adding it as a closer stopped the consolidated statements chapter from swallowing the standalone accounts that follow it (Tata Motors FY24: 281–480 → 281–385).
- **The rupee sign is unreliable in extracted text.** Depending on the font it comes out as "₹", a backtick, "H", "C", "I", "K" or a Tibetan digit; TCS FY25 also maps the digit 4 to "ϰ" in places. Section detection doesn't care, but amount extraction (week 3) has to — every figure must be read from context ("… crore"), never from the currency glyph.
- **chromadb** 0.5 has no Python 3.13 Windows wheel for its HNSW dependency (needs a C++ toolchain), so the vector index is FAISS.

Known gaps (parser v1.3): HDFC Bank FY24's Chairman's letter is not detected, and FY25's runs on through the board profiles (p10–60) because nothing closes it; L&T FY24 p355 ("Annexure to the Board Report — Management Discussion & Analysis: please refer to pages 18 to 127") is a one-line cross-reference that opens a false MD&A; Reliance FY25 and Sun Pharma have no standalone Risk chapter (risk discussion sits inside the MD&A, which is labelled correctly); ICICI's MD&A PDF is not yet in `sources.csv`. `python -m arqa.parse --peek <STEM> <page> …` shows exactly what the parser sees on a page — it is how every item above was found.
